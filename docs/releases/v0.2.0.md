# FairShare v0.2.0 - Household Foundation

**Status:** Prerelease for one trusted household  
**Target tag:** `v0.2.0`

This prerelease establishes Household as FairShare's primary domain concept and prepares the application structure for future multi-household support. It does not complete household authorization or data isolation.

## Changed

- Renamed the Room model and application terminology to Household.
- Moved household endpoints from `/api/rooms` to `/api/households`.
- Updated household-facing frontend state and Socket.IO event names.
- Introduced `householdId` alongside transitional `roomId` fields on household-owned records.
- Assigned a household to newly created chores, expenses, and events, retaining the temporary shared default-household fallback when `householdId` is omitted.
- Kept household documents in MongoDB's existing `rooms` collection.
- Restricted household updates to the `name` field.
- Updated the README, API reference, architecture, and development documentation.

## Compatibility

Household documents remain in the `rooms` collection, and the existing-data migration has not been run. Some models retain `roomId` compatibility fields; chat history also reads legacy `roomId` messages. The presence of these fields does not mean resource access is isolated by household.

## Known limitations

- Chores, expenses, events, and roommate endpoints are not consistently scoped by household or membership.
- Some resource operations look up records by ID without checking household membership.
- `householdId` remains optional on some resource models, and shared default-household behavior remains for some writes.
- Membership is embedded in `Household.members`; roles and invitation lifecycle management are incomplete.
- Invitation codes use `Math.random()` and do not have expiration or revocation controls.
- The active-household selector is available only in Chat.
- Cross-household security tests and the legacy data migration are not complete.

This release is not safe for unrelated households. Do not treat the selected household in the frontend as authorization.
